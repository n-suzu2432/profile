# HTML・React・Next.js まとめ

---

## 1. ひとことで言うと

| | 種類 | ひとこと |
|---|---|---|
| HTML | マークアップ言語 | 書いたものがそのまま表示される |
| CSS | スタイルシート言語 | デザインを書く言葉 |
| JavaScript | プログラミング言語 | 動きや機能を書く言葉 |
| React | ライブラリ | JavaScriptの便利な部品集 |
| Next.js | フレームワーク | Reactをさらに使いやすくした道具箱 |

> **Next.jsはプログラミング言語ではない。**  
> 中身はJavaScriptで書く。Next.jsはあくまで「枠組み」。

---

## 2. それぞれの関係

```
┌─────────────────────────────┐
│           Next.js            │
│  ┌───────────────────────┐  │
│  │         React          │  │
│  │  ┌─────────────────┐  │  │
│  │  │   JavaScript    │  │  │
│  │  └─────────────────┘  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

- JavaScriptの上にReactがある
- ReactをさらにつつんでいるのがNext.js
- Next.jsを使えばReactもJavaScriptも全部使える

料理で例えると…

| | 例え |
|---|---|
| JavaScript | 食材（肉・野菜・調味料） |
| React | 調理器具（フライパン・包丁） |
| Next.js | 厨房（調理器具・レシピ・設備が全部そろったキッチン） |

## 3. HTMLとは

ウェブページを作るための**一番基本の言語**。  
ブラウザに対して「こう表示して」と指示を書く言葉。

```html
<h1>こんにちは</h1>        ← 大きな見出し
<p>私は薬剤師です。</p>    ← 普通の文章
<img src="photo.jpg">      ← 画像を表示
```

### 3つの言語をセットで使う

| 役割 | 言語 | 例え |
|---|---|---|
| 構造・内容 | HTML | 家の骨組み |
| デザイン・色 | CSS | 壁紙・インテリア |
| 動き・機能 | JavaScript | 電気・水道 |

### 動く仕組み

サーバーもビルドも不要。ファイルをダブルクリックするだけで動く。

```
index.html → ブラウザが読む → 表示される
```

---

## 4. Reactとは

Facebookが2013年に作ったJavaScriptの仕組み。  
**ページを「部品（コンポーネント）」に分けて組み立てる**考え方。

### なぜReactが生まれたか

HTMLだけで大きなサイトを作ると…

```
・ヘッダー
・タイムライン
・サイドバー
・チャット
・広告
・通知バッジ　…
```

これを全部1つのHTMLファイルに書いたら何万行にもなる。  
「いいね！ボタン」のデザインを変えたいとき、全ページ探して直す必要がある。

→ **「部品として分けて作れないか？」** という発想から生まれた。

### レゴブロックのイメージ

```
HTMLの考え方：1枚の絵を描く
└── index.html（全部ここに書く）

Reactの考え方：レゴブロックを組み合わせる
├── ヘッダー部品
├── メインコンテンツ部品
├── サイドバー部品
└── フッター部品　→ 全部組み合わせてページを作る
```

**ブロックを1つ直せば、そのブロックを使っている全ページが一気に変わる。**

### ページを丸ごと更新しなくていい

```
【HTMLの場合】
「いいね！」を押す → ページ全体をリロード → また最初から全部表示し直す

【Reactの場合】
「いいね！」を押す → いいねボタンの数字だけ変わる → 他は何も変わらない・一瞬で反映
```

### Reactのコードイメージ

```jsx
// 「いいねボタン」という部品を作る
function いいねボタン() {
  return (
    <button>❤️ いいね！</button>
  );
}

// どこでも使い回せる
<いいねボタン />
<いいねボタン />
<いいねボタン />
```

## 5. Next.jsとは

Reactをさらに使いやすくした**フレームワーク**。  
「よく使う機能をあらかじめ全部用意しておいた道具箱」。

### Reactだけだと困ること

```
Reactだけで作ろうとすると自分で設定するもの：
・URLとページの対応
・画像を軽くする処理
・SEO設定
・読み込みを速くする工夫
・サーバーとのデータのやり取り　…
```

→ Next.jsはこれを**最初から全部用意してくれている**。

### Next.jsが用意してくれるもの

| 機能 | 内容 |
|---|---|
| ページのURL管理 | フォルダを作るだけでURLが決まる |
| 画像の最適化 | 重い画像を自動で軽くしてくれる |
| SEO設定 | Googleに見つけやすくする設定が簡単 |
| ページの自動生成 | 記事データを用意するだけでページが自動で増える |
| サーバー機能 | データベースとの連携 |

### 動く仕組み

一度「ビルド」という変換作業が必要。

```
コード（.tsx）→ ビルド → HTML・JS・CSSに変換 → ブラウザが読む
```

HTMLと違い、人間が書くコードとブラウザが読むコードが別物になる。

## 6. メリット・デメリット比較

### HTML

| | 内容 |
|---|---|
| ✅ メリット | すぐ始められる・ファイルを開くだけで動く |
| ✅ メリット | 覚えることが少ない（HTMLとCSSだけでOK） |
| ✅ メリット | 軽くて速い |
| ✅ メリット | トラブルが少ない・シンプルで壊れにくい |
| ❌ デメリット | 更新のたびに全ファイルを直す必要がある |
| ❌ デメリット | ログインや動的な表示などはHTML単体では無理 |
| ❌ デメリット | ページが増えると管理が大変 |

### Next.js

| | 内容 |
|---|---|
| ✅ メリット | 1か所直すだけで全ページに反映される |
| ✅ メリット | ページを自動生成できる |
| ✅ メリット | ログイン・検索・決済など複雑な機能も作れる |
| ✅ メリット | SEOに強い |
| ❌ デメリット | 始めるまでの準備が多い |
| ❌ デメリット | JavaScriptの知識が必要 |
| ❌ デメリット | エラーの原因が複雑でわかりにくい |
| ❌ デメリット | 小さなサイトにはオーバースペック |

### 2つを並べて比較

| 項目 | HTML | Next.js |
|---|---|---|
| 始めやすさ | 簡単 | 難しい |
| 更新のしやすさ | ページ数が増えると大変 | 楽 |
| 表示速度 | 速い | 設定次第 |
| 動的な機能 | 不可 | 可能 |
| 学習コスト | 低い | 高い |
| 向いているサイト規模 | 小〜中 | 中〜大 |

## 7. Next.jsで作って困ること

「全部Next.jsで作る」はプロの開発者でも普通にやること。  
ただし**今の段階**では困ることがたくさん出てくる。

### 困ること① 動かすまでが大変

```
HTMLの場合：
ファイルを作る → ブラウザで開く → 完成

Next.jsの場合：
Node.jsをインストール → プロジェクトを作成 →
パッケージをインストール → 開発サーバーを起動 →
ビルド → Vercelにデプロイ → 完成
```

何かトラブルがあると、どのステップで詰まっているかわからなくなる。

### 困ること② エラーメッセージが難しい

```
HTMLのエラー：
「画像が表示されない」→ ファイル名が間違ってるだけ

Next.jsのエラー：
Error: Cannot read properties of undefined (reading 'map')
    at Home (./pages/index.js:12:20)
    at processChild (/node_modules/...)
    ...
```

初心者には原因がわかりにくい。

### 困ること③ 覚えることが多すぎる

```
JavaScript　← まず必須
　↓
Reactの書き方
　↓
Next.js独自のルール
　↓
Node.jsの知識
　↓
npmコマンドの知識
　↓
デプロイの知識
```

HTMLなら「HTMLとCSS」だけでよかったのが、6段階分の知識が必要になる。

### 困ること④ 今の課題が解決しない

Next.jsを使っても、今抱えている問題（デプロイ・デザイン）は別の話。

| | 内容 |
|---|---|
| 今の課題 | HTMLでポートフォリオを作る・Vercelで公開・デザインを整える |
| Next.jsで解決すること | 大量ページの自動生成・ログイン機能・データベース連携 |

**今の課題とNext.jsが解決することがズレている。**

> 楽に見えるのは「使いこなせたあとの話」。  
> 使いこなすまでの道のりがHTMLより何倍も大変。

## 8. どちらを使うか　判断の目安

| 質問 | HTMLでOK | Next.jsを検討 |
|---|---|---|
| ページは何枚？ | 〜10枚くらい | 何十・何百枚 |
| 内容は変わる？ | ほぼ変わらない | 頻繁に更新する |
| データと繋ぐ？ | 不要 | 必要 |
| ログイン機能？ | 不要 | 必要 |

**重要：「ページ数が増えたからNext.js」ではなく、「データが頻繁に変わるかどうか」が本当の判断基準。**

- プロフィールページが3〜5枚に増えた → **HTMLで十分**
- ブログ記事を毎週追加したい → **Next.jsを検討**
